# Changelog

버전은 4개 SDK(iOS·Android·Web·Flutter) **lockstep**이다 — 자기 플랫폼에 변경이 없어도 같은 번호로
동시 릴리스한다(기획서 6.5). 골든 벡터가 언어 무관 계약이므로 버전 번호가 곧 "어느 조합이 정합인가"의
답이다. 0.x 구간에서는 **마이너 올림이 breaking change 신호**이며, 트리거는 직렬화(11.1)·매칭(11.3)·
골든 벡터 스키마 변경이다.

## 0.1.0

첫 공개 릴리스.

- **2계층 resolve** — 빌드타임에 구운 번들(fallback) 위에 런타임 원격 오버레이를 키 단위로 덮는다.
  오버레이는 sparse, 적용은 원자적(체크섬 후 스왑), tombstone(삭제 마커) 지원.
- **로케일 fallback 체인** — BCP 47 태그를 구체→일반으로 절단(`ko-KR → ko → 기본 로케일`)하되
  각 로케일 단계 안에서 오버레이·번들을 모두 확인한 뒤 다음 로케일로 넘어간다(로케일 우선 원칙).
  조회 로케일은 `RynL10nClient(locale: ...)`로 정하며 **릴리스 매칭 축과 별개다**.
- **포맷 안전 가드** — 오버레이 값의 플레이스홀더 서명이 번들과 다르면 그 키만 번들로 물러난다.
  잘못된 원격 문자열로 인한 런타임 크래시를 차단한다.
- **버전 격리** — 정적 manifest를 클라이언트가 읽어 자기 앱 버전에 맞는 릴리스를 스스로 고른다
  (서버 라우팅 없음). 매칭 전략 3종: `semver-range` · `exact-label` · `integer-range`.
- **갱신 3종** — 수동 `update()` · 주기 폴링(보장선) · SSE 푸시(지연 단축, 옵트인).
- **익명 집계 텔레메트리**(옵트인 2겹) — 수집·전송 각각 켜야 하며 서버 스키마 5개 필드만 올라간다.
  키 이름·번역 값·기기 식별자는 구조적으로 나가지 않는다.
- **어댑터 분리** — 코어(`rynl10n.dart`)는 HTTP·저장소를 주입받는 순수 Dart다. 진입점은 둘 중 택일:
  `rynl10n_io.dart`(`dart:io`, 추가 의존성 0, 웹 컴파일 불가) ·
  `rynl10n_http.dart`(`package:http`, Flutter Web 포함 전 플랫폼).
- 코어 알고리즘(JCS 정규화·해시·resolve·매칭·카나리)은 TS 참조 구현과 **골든 벡터로 바이트·해시·동작
  정합**을 기계 검증한다 — 4개 언어가 같은 벡터를 읽는다.

**알려진 제약**: Flutter Web에서 `httpPushConnect`는 SSE가 스트리밍되지 않는다(BrowserClient=XHR).
웹은 `EventSource`를 `PushConnect`로 감싸 넣으면 되고, 그대로 둬도 폴링이 보장선이라 기능은 깨지지
않고 갱신 지연만 남는다.
